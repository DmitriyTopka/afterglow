# Eval v3: tool-using agent vs Claude alone vs the old pipeline (06.10.2026)

Same 40 frozen blind scenarios (eval/v2_scenarios.json). Arms:
- agent: the live tool-using agent (Claude Haiku 4.5 driving Qloo tools), first 3 picks.
- claude-only: the same model reads the whole 384-title catalog as text (id, title, format, price) and picks 5. No Qloo.
- pipeline: the fixed pipeline the agent replaced.
Pooled = labels plus a second blind judge on every unlabelled pick (33 yes / 125 no this round).
Odd scenarios were used on 06.10 to choose the ranking, so the even half is the clean comparison.

| set | metric | agent | claude-only | pipeline | agent vs claude W/L |
|---|---|---|---|---|---|
| all 40 | labels P@3 | 0.40 | 0.29 | 0.35 | 19/8 |
| all 40 | pooled P@3 | 0.56 | 0.43 | 0.47 | 21/10 |
| even 20 (clean) | labels P@3 | 0.38 | 0.37 | 0.38 | 8/6 |
| even 20 (clean) | pooled P@3 | 0.50 | 0.55 | 0.50 | 7/8 |

By group (all 40, pooled): tastes in store 0.60 / 0.45 / 0.45; not in store 0.48 / 0.38 / 0.40; multi-format 0.63 / 0.50 / 0.60.
Budget: claude-only put 12 over-budget titles in its top 3; agent and pipeline 0.
Agent cost: 3.3 model turns on average, 68 live Qloo calls for 40 requests (rest cached), ~$0.008 per request.

Reading
- Over all 40 the agent beats Claude alone clearly, but on the 20 scenarios never used for tuning it is a tie.
  The honest claim is: as good as a strong LLM reading the whole catalog, while respecting budgets, explaining
  which taste drove each pick, and producing the store check that feeds the owner side.
- Claude alone only works because this catalog fits in a prompt (384 titles, about 12k tokens). A real store
  with tens of thousands of titles does not; Qloo scoring does not depend on catalog size in the prompt.
- Not shown here: the owner-side value (coverage, stock suggestions, cold start) has no Claude-only counterpart.
